# WSDL no XSD Visualizer

## Problem Statement

Os web services da SEFAZ (NF-e, NFCom, NF3e, NFGas…) são SOAP descritos por WSDL, mas o WSDL não diz o que vai dentro do Body: declara um elemento de conteúdo livre (`nfeDadosMsg` = `xs:any`) ou uma string compactada. Para montar ou depurar uma chamada é preciso juntar à mão o envelope SOAP, a versão certa do SOAP, o `soapAction`, os headers e o XML de negócio do pacote de schemas — e, quando algo é rejeitado, descobrir se o problema está no envelope, no corpo ou no XML de negócio.

## Solution

O XSD Visualizer passa a ler os `.wsdl` que estão na pasta de um Schema Set. Cada Schema Set mostra seus **Services** e **Operations**. Numa Operation, o usuário escolhe o **Endpoint** (SOAP 1.1 ou 1.2) e faz o **Payload Binding** da Request e da Response (qual Global Element vai no Body e se vai compactado). Os botões Minimal, Maximal e Coverage Set passam a gerar **Envelopes** completos e válidos. Um Envelope trazido pelo usuário é vinculado à Operation e validado em camadas: envelope SOAP, corpo do WSDL e Payload.

## User Stories

1. Como analista fiscal, quero que os `.wsdl` da pasta de um Schema Set sejam carregados junto com os XSDs, para ver os serviços e os schemas no mesmo lugar.
2. Como analista fiscal, quero arrastar um `.wsdl` solto e ter a pasta dele aberta como Schema Set, como já acontece com `.xsd`.
3. Como analista fiscal, quero ver, em cada Schema Set, um grupo "Serviços" com os Services e suas Operations.
4. Como desenvolvedor, quero ver a Validation Issue de carga quando um WSDL for 2.0, `rpc` ou `encoded`, para saber que ele está fora do que o app suporta.
5. Como desenvolvedor, quero ver a Validation Issue de carga quando um WSDL estiver malformado ou referenciar mensagens, bindings ou elementos inexistentes.
6. Como analista fiscal, quero selecionar uma Operation e ver seus Endpoints com endereço, versão do SOAP e `soapAction`.
7. Como analista fiscal, quero escolher o Endpoint de uma Operation, com SOAP 1.2 como padrão quando existir, para gerar o Envelope da versão certa.
8. Como analista fiscal, quero alternar entre a Request e a Response da Operation selecionada.
9. Como analista fiscal, quero escolher o Global Element do Payload da Request e da Response (Payload Binding), porque o WSDL não diz qual é.
10. Como analista fiscal, quero que o Payload Binding fique salvo, para não refazer a escolha a cada vez.
11. Como analista fiscal, quero marcar o Payload como compactado (gzip+base64), já marcado quando o Body é uma string, para as recepções compactadas da NFCom/NF3e/NFGas e as operações `Zip`.
12. Como analista fiscal, quero ver a árvore do Payload vinculado ao selecionar a Request/Response, com o mesmo painel de detalhes de hoje.
13. Como analista fiscal, quero gerar o Envelope Minimal, Maximal e o Coverage Set de Envelopes de uma Request ou Response.
14. Como analista fiscal, quero que o Envelope gerado use o namespace do SOAP do Endpoint escolhido.
15. Como analista fiscal, quero que os headers SOAP declarados no WSDL apareçam no `Header` do Envelope.
16. Como analista fiscal, quero que, sem Payload Binding, o Envelope saia marcado inválido com a mensagem "defina o Payload Binding", em vez de um Envelope silenciosamente incompleto.
17. Como analista fiscal, quero que, numa mensagem compactada, o Envelope traga o Payload em gzip+base64 e o Payload legível seja aberto ao lado.
18. Como analista fiscal, quero que cada Envelope do Coverage Set diga no topo o que cobre, como os Samples de hoje.
19. Como analista fiscal, quero que os Envelopes sejam determinísticos, para comparar versões com diff.
20. Como analista fiscal, quero salvar e copiar Envelopes como qualquer Sample.
21. Como analista fiscal, quero que "gerar todos" inclua os Envelopes das Operations com Payload Binding, em `_servicos/<Service>/<operation>.{request|response}.{min,max,cov-NN}.xml`.
22. Como analista fiscal, quero arrastar um Envelope capturado de um log e ter ele vinculado automaticamente à Operation pelo elemento do Body.
23. Como analista fiscal, quero escolher a Operation quando houver mais de uma candidata.
24. Como analista fiscal, quero que o Envelope trazido seja validado contra o schema do SOAP, contra o schema do WSDL e o Payload contra o seu Global Element, com todas as Validation Issues numa lista só.
25. Como analista fiscal, quero que o Payload de um Envelope trazido seja vinculado ao Global Element pelo Payload Binding salvo ou, sem ele, pela raiz do Payload (como o Binding de Document).
26. Como analista fiscal, quero que um Payload compactado seja descompactado para validar, e aberto numa aba própria onde as Validation Issues apontam as linhas.
27. Como analista fiscal, quero que a revalidação ao digitar funcione também para Envelopes.

## Implementation Decisions

- **Escopo (ADR-0004):** WSDL 1.1, `document`/`literal`, SOAP 1.1 e 1.2. WSDL 2.0, `rpc`, `encoded` e bindings não-SOAP viram Validation Issues de carga. Sem execução de chamadas e sem "Abrir URL".
- **Carga:** o carregador do Schema Set também lê os `.wsdl` da pasta. Os `xs:schema` de `wsdl:types` são compilados numa unidade própria por WSDL (como os arquivos raiz de XSD, ADR-0003), herdando os prefixos declarados no `wsdl:definitions`. Esses elementos de invólucro (ex.: `nfeDadosMsg`) não entram na lista de Global Elements.
- **Modelo (Core):** Service (nome, arquivo, Endpoints, Operations); Endpoint (nome, endereço, versão do SOAP, `soapAction` por Operation); Operation (nome, Service, Request, Response); cada mensagem conhece o elemento do Body, os headers declarados e se o Body é string. Payload Binding = Global Element + compactado.
- **Geração:** a Operation gera Envelopes a partir de (Request ou Response, Endpoint, Payload Binding, Minimal/Maximal/Coverage Set). O Payload é gerado pelo Global Element vinculado; o Envelope por fora é fixo. Body de conteúdo livre recebe o Payload como elemento filho; Body string recebe o Payload como texto, compactado em gzip+base64 se marcado. Headers são gerados com o gerador de sempre (modo Maximal). O comentário "cobre" do Coverage Set vai no topo do Envelope.
- **Sample:** passa a poder representar um Envelope: sabe a Operation e a direção, o nome de arquivo segue `<operation>.{request|response}.{min,max,cov-NN}.xml`, guarda o Payload legível quando compactado e sabe se revalidar.
- **Validação de Envelope:** numa só passada, com um conjunto de schemas que junta o schema oficial do SOAP (1.1 e 1.2, embutidos), o schema do WSDL e o do Global Element do Payload, para que as posições apontem para o Envelope. Payload compactado: descompacta e valida à parte; as Validation Issues desse Payload se referem ao texto descompactado.
- **Binding de Envelope:** um Document cuja raiz é `Envelope` do SOAP é vinculado às Operations cujo elemento do Body (Request ou Response) casa com o primeiro filho do Body; um candidato liga sozinho, vários o usuário escolhe. O Global Element do Payload vem do Payload Binding salvo ou, sem ele, da raiz do Payload.
- **Exportação:** "gerar todos" recebe os Payload Bindings e inclui os Envelopes das Operations vinculadas; Operations sem Payload Binding ficam de fora.
- **App:** o grupo "Serviços" entra na árvore da esquerda; ao selecionar uma Operation, a coluna do meio mostra seletor de Endpoint, alternância Request/Response, Payload Binding (Global Element + compactado) e a árvore do Payload; os botões de gerar produzem Envelopes. Payload Bindings e Endpoint escolhido ficam na sessão.

## Testing Decisions

- Mesmo seam de hoje: a fachada pública do Core. Carga (Services na SchemaSet), geração (Envelopes da Operation), Binding de Document (Envelopes) e validação (três camadas). Nenhum seam novo.
- Oráculo: o validador do .NET. Todo Envelope gerado com Payload Binding precisa validar nas três camadas; o Payload compactado é descompactado e comparado com o Sample do Global Element.
- Fixtures sintéticas, uma por caso: SOAP 1.1, SOAP 1.2, os dois, Body `xs:any`, Body string compactado, header, `rpc` e WSDL 2.0 rejeitados.
- Integração: WSDLs reais da NF-e 4.00 (SVRS e SP) com o PL_010 e os quatro WSDLs da NFCom (só carga, sem pacote de XSD da NFCom).
- Interface sem testes automatizados.

## Out of Scope

- WSDL 2.0, `rpc`, `encoded`, bindings HTTP/MIME, WS-Policy, WS-Security.
- Executar chamadas, certificado digital, "Abrir URL" de `?wsdl`.
- Adivinhar o Payload Binding por convenção de nomes; arquivo de mapeamento compartilhável (fica para depois).
- Assinatura digital real no Payload.

## Further Notes

- Glossário: Service, Endpoint, Operation, Request/Response, Payload, Payload Binding, Envelope (CONTEXT.md).
- Os WSDLs da SEFAZ não são públicos nos endpoints (403 sem certificado); os de teste vêm de repositórios públicos e podem divergir do que os serviços servem hoje.
